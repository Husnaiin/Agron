# Agron Artificial GCS Server

This is an artificial Ground Control Station (GCS) server that replicates the functionality of `server1.py` but generates dummy telemetry data instead of connecting to real hardware. It's designed for testing the frontend application without requiring actual drone hardware.

## Features

- **Artificial Telemetry Generation**: Simulates drone position, altitude, speed, heading, battery, and spray levels
- **Mission Management**: Handles mission start, pause, resume, stop, and emergency return commands
- **Waypoint Logging**: Logs waypoints received from frontend and generated by the system for comparison
- **WebSocket Communication**: Same WebSocket API as the real server
- **Mission Simulation**: Simulates drone movement along waypoints

## Installation

1. Install Python dependencies:
```bash
pip install -r requirements_artificial.txt
```

## Usage

### Starting the Server

```bash
python server.py
```

The server will start on `http://localhost:5001` with WebSocket endpoint at `ws://localhost:5001/ws/telemetry`.

### Connecting from Flutter App

In your Flutter app, connect to the artificial server using:
- IP Address: `localhost` or `127.0.0.1`
- Port: `5001`

## Waypoint Logging

The server automatically logs waypoints to text files in the `./waypoint_logs/` directory:

- **`frontend_waypoints_YYYYMMDD_HHMMSS.txt`**: Waypoints received from the frontend
- **`uploaded_waypoints_YYYYMMDD_HHMMSS.txt`**: Waypoints uploaded to the server

The Flutter app also logs generated waypoints:
- **`dense_inspection_generated_TIMESTAMP.txt`**: Dense inspection waypoints generated by the app
- **`simple_inspection_generated_TIMESTAMP.txt`**: Simple inspection waypoints generated by the app

## Testing Mission Types

### Simple Inspection
1. Select "Inspection" from the mission type dropdown
2. Draw waypoints on the map
3. Start the mission
4. Check the log files to see:
   - Convex hull waypoints generated by the app
   - Same waypoints received by the server

### Dense Inspection
1. Select "Dense Inspection" from the mission type dropdown
2. Draw waypoints on the map
3. Start the mission
4. Check the log files to see:
   - Dense coverage path waypoints generated by the app
   - Same waypoints received by the server

## API Endpoints

- `GET /status`: Server health check and status
- `GET /waypoints`: Get current mission waypoints
- `WebSocket /ws/telemetry`: Main communication endpoint

## WebSocket Message Types

### From Client to Server:
- `start_mission`: Start a mission with waypoints
- `pause_mission`: Pause the current mission
- `resume_mission`: Resume the paused mission
- `stop_mission`: Stop the current mission
- `emergency_return`: Trigger emergency return
- `upload_mission`: Upload mission waypoints
- `capture_rgb`: Capture RGB image
- `capture_noir`: Capture NoIR image
- `ping`: Ping the server

### From Server to Client:
- `connection_status`: Connection confirmation
- `telemetry`: Artificial telemetry data
- `mission_status`: Mission status updates
- `capture_status`: Capture command confirmations
- `pong`: Response to ping

## Comparison Testing

To verify that waypoints are correctly sent from frontend to backend:

1. Run the artificial server
2. Connect the Flutter app to the server
3. Create a mission with either inspection type
4. Start the mission
5. Compare the log files:
   - Frontend generated waypoints should match server received waypoints
   - For dense inspection, you should see many more waypoints than simple inspection
   - All waypoints should have the same coordinates and properties

## Differences from Real Server

- No MAVLink connection
- No camera capture (simulated responses only)
- Artificial telemetry generation instead of real sensor data
- Simplified mission execution (no actual flight control)
- Waypoint logging for debugging and comparison

This artificial server is perfect for:
- Testing frontend functionality
- Debugging waypoint generation algorithms
- Verifying mission type differences
- Development without hardware dependencies
